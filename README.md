```bash

```

`--string` uses the exact UTF-8 content delivered in that one shell argument. The shell removes the surrounding quotes before Grimchain receives it. Grimchain adds no newline, performs no trimming or normalization, and does not use a separate string algorithm. Omitting the number uses the compact Shadow Locus `⛎` center; supplying a number uses exactly that many Synodic Magicae characters. The ordinary middle, nonce, output, and verification rules remain unchanged.

Shell quoting still belongs to the shell. Single quotes preserve characters such as `$HOME` literally, while double quotes may allow the shell to expand them before Grimchain receives the resulting string.

### Create manifests

```bash
grimchain 64 --manifest file.bin
grimchain 64 --manifest directory
grimchain 64 -R --manifest directory
grimchain 64 --manifest directory --output chosen-name.grim
```

The command first writes the complete manifest body and the waiting `THIS FILE` line. It then Grimchains that prepared `.grim` using the exact middle selected by the user, appends only that Grimchain and one terminal newline, Grimchains the completed `.grim` again at the same middle, and prints the final result. The stored `THIS FILE` value and the terminal output are byte-identical.

Omitting `NUMBER` uses the compact Shadow Locus `⛎` center throughout. Supplying `NUMBER` uses exactly that many Synodic Magicae characters for every manifest entry, the manifest-body Grimchain, the first `THIS FILE` pass, and the final confirming pass. No smaller display depth or separate manifest default is substituted.

The physical ending is:

```text
THIS FILE
🜛...the exact user-depth Grimchain...🜛
```

The `THIS FILE` header exists before the first self-chain. After that first pass, only the Grimchain itself and its final newline are appended.
